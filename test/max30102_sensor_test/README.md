# MAX30102 단독 시험 — Teensy 4.1

모든 모터 주전원을 물리적으로 분리한 센서 벤치 시험용입니다.
업로드하면 이전 모터 시험 스케치는 교체됩니다. 이 코드는 모터를 구동하지 않습니다.
두 음압 모터의 EN(26/37), VSP(24/33)를 정적 LOW로 초기화하지만, 부팅 전·배선 오류·
드라이버 고장까지 막는 기능이 아닙니다. 모터 전원 분리를 대신하지 않습니다.

**2026-10-02:** 음압 모터 2 EN 보호 핀도 35→37로 옮겼습니다.
35번은 WT901C Serial8 TX 예약이므로 이 PPG 시험에서 출력 LOW로 사용하지 않습니다.
NAU7802는 독립 Wire1(17/16), PPG는 기존 Wire(18/19)를 사용합니다.

## 핀맵

| 모듈 신호 | Teensy 4.1 / 연결 | 이유 |
|---|---|---|
| VIN | **3.3V 입력을 지원하는 모듈이면** Teensy 3.3V | 3.3V 논리 환경으로 시험. 모듈 전원 사양 확인 필수 |
| GND | Teensy GND | 공통 신호 기준 |
| SDA | 디지털 **18** | 기본 `Wire` 데이터 핀 |
| SCL | 디지털 **19** | 기본 `Wire` 클록 핀 |
| SDA 풀업 | SDA와 **3.3V 사이에 4.7kΩ** | 오픈드레인 버스의 HIGH 생성 |
| SCL 풀업 | SCL과 **3.3V 사이에 4.7kΩ** | SDA와 별도의 풀업 필요 |
| INT | 미연결 | I2C로 FIFO/상태 레지스터를 폴링 |
| RD / IRD | 미연결 | 이 시험의 외부 연결 대상이 아님 |

사진의 Arduino UNO A4/A5와 5V 풀업을 그대로 따라 하지 마세요.
Teensy SDA=18/SCL=19이며 GPIO는 5V tolerant가 아닙니다.
이미 모듈에 풀업이 있으면 연결 전 그 저항이 어느 전원에 연결됐는지 확인하세요.
기존 5V 풀업을 둔 채 3.3V 풀업을 추가하는 것은 레벨 변환이 아닙니다.
모듈에 1.8/3.3V 풀업 선택 패드가 있다면 Teensy 쪽은 3.3V로 설정합니다.
확인된 3.3V 풀업이 이미 충분히 있다면 외부 4.7kΩ을 중복 추가하지 않습니다.

**모듈 VIN과 센서 칩 VDD는 다릅니다.** MAX30102 칩은 코어 1.8V와 LED 전원을 사용합니다.
사진만으로 모듈의 레귤레이터/레벨 변환 구조를 확정할 수 없습니다.
VIN이 5V 전용인 모듈이면 모듈 사양대로 별도 전원을 쓰되, Teensy에 닿는 SDA/SCL은
여전히 0~3.3V여야 합니다. 모듈 사양 확인 전 5V로 임의 변경하지 마세요.
Teensy를 연결하기 전 전원이 들어온 모듈의 SDA/SCL 유휴 전압을 확인합니다.

## IDE 설정과 사용

1. `max30102_sensor_test.ino`를 열고 같은 폴더의 `pinmap.h`, `optical_window.h`,
   `ppg_diagnostics.h`, `ppg_signal.h`도 유지합니다.
2. 보드: **Teensy 4.1**, USB Type: **Serial**.
3. 라이브러리 관리자에서 **SparkFun MAX3010x Pulse and Proximity Sensor Library**를 설치합니다.
   현재 개발 PC에는 1.1.2가 있습니다. 이 스케치는 그 안의 `spo2_algorithm.h`를 사용합니다.
4. 모터 주전원을 분리하고 센서를 배선한 뒤 업로드합니다.
5. 시리얼 모니터: **115200, 새 줄(Newline)**. 센서 취득은 자동 시작합니다.

| 명령 | 동작 |
|---|---|
| `HELP` | 명령 안내 |
| `STATUS` | 취득 여부, 연결 여부, 마지막 ID, 누적 샘플/오류/로그 누락 |
| `READ` | 최신값 1회 출력. 새 샘플을 기다리지 않음 |
| `STOP` | 취득/자동 재연결 중지, 연결돼 있으면 센서 shutdown 요청 |
| `START` / `RETRY` | 센서 리셋·재설정 후 취득 재개 |
| `CAL OPEN` / `CAL FINGER` | 미접촉/접촉 광량을 각각 신규 250쌍(약 10초) 수집 |
| `CAL_SHOW` / `CAL_APPLY` / `CAL_RESET` | 제안 확인/수동 적용/기본 접촉 기준 복원 |
| `MODE RAW` / `MODE DATA` / `MODE PLOT` | 25Hz 원시 기록/10Hz 요약/표시용 AC 파형 |
| `LED 1..255` | LED 전류 코드 변경. 접촉 보정·계산 창 초기화 |

`STOP`은 모터 정지 명령이 아닙니다. I2C가 고장 나면 LED shutdown도 보장할 수 없으며
`SHUTDOWN_FAILED`가 나옵니다. 필요하면 전원을 끄고 배선을 점검합니다.

기동 문구: `SAVER_MAX30102_SENSOR_TEST_READY,build=pulse_quality_v3`.
이 문구와 `DATA`의 `contact=` 필드가 없다면 이전 코드가 업로드된 상태일 수 있습니다.
`SENSOR_CONNECTED`는 주소 0x57, ID 0x15, 설정 레지스터 읽기 검증이 통과했다는 뜻입니다.
ID 0x15는 MAX30102/MAX30105가 공유하므로 칩 모델을 유일하게 식별한 것은 아닙니다.
MAX30100 등 다른 칩은 호환된다고 가정하지 않고 `UNSUPPORTED_PART_ID`로 거부합니다.

## 손가락을 뗐는데 숫자가 남는 문제 보완

`optical_window.h`에서 두 광학 채널을 함께 검사합니다. 핀 배정·LED 세기·샘플레이트는
변경하지 않았습니다. 아래 값은 **현재 모듈/설정의 시험용 광량 판별값**이며,
의학적 임계값이나 피부/생체 식별 기능이 아닙니다.

| 설정 | 값 | 의미 |
|---|---:|---|
| `CONTACT_ON_RAW` | 50,000 | RED와 IR이 모두 이 값 이상이어야 접촉 후보 진입 |
| `CONTACT_OFF_RAW` | 30,000 | 어느 한 채널이라도 이 값 이하면 즉시 후보 해제 |
| `CONTACT_SETTLE_MS` | 500 ms | 진입 광량이 연속 유지돼야 계산용 샘플 수집 시작 |
| `CONTACT_MAX_GAP_MS` | 200 ms | 새 샘플이 이 시간 동안 없으면 후보/추정값 폐기 |

설정 근거: 사용자가 제공한 2026-09-07 로그에서 손을 대지 않은 구간은
RED 약 10,700 / IR 약 18,300, 손을 뗀 후반은 두 채널 약 1,000,
접촉 구간은 RED 약 200,000 / IR 약 220,000이었습니다. 경계값은 이 구간을
분리하기 위한 초기 공학 설정이며 다른 센서·주변 물체·LED 설정에서 재검증해야 합니다.

- 손을 뗀 저광량 **첫 샘플**에서 `hr_ok=0`, `spo2_ok=0`, `window_samples=0`으로 바꿉니다.
  `hr_bpm`, `spo2_pct` 숫자 필드는 생략합니다. 다음 1초 계산까지 이전 값을 유지하지 않습니다.
- 접촉 후보를 다시 확인한 뒤 **새로운 200개 샘플**을 모두 모아야 품질을 검사합니다.
  최초 또는 재접촉 후 첫 품질 검사는 약 0.5초 안정화 + 8초 수집 뒤입니다.
  연속된 두 창의 주기가 일치해야 수치를 출력하므로 처음에는 약 9.5초 이상 걸립니다.
- 단 한 채널의 저광량, ADC 최대 코드, 통신 실패, STOP/START/RETRY도 이전 계산 창을 폐기합니다.
- 원시 광량은 미접촉 때도 계속 출력합니다. 원시값 출력과 생체값 유효성은 별개입니다.
- 심박수는 새 `ppg_signal.h`의 반복 주기 검사로 계산합니다. SpO2는 기존
  SparkFun/Maxim 알고리즘을 사용하되 새 품질 검사와 주기 일치 조건을 추가했습니다.
  주기적인 반사 물체·진동도 통과할 수 있습니다. 기준 장비 비교는 별도입니다.

`contact=NONE` 또는 `SETTLING`일 때는 심박수·SpO2 숫자가 없어야 합니다.
`contact=CANDIDATE`는 두 채널의 광량 조건을 만족했다는 뜻일 뿐,
실제 손가락·유효 맥박·의학적 정확도가 확인됐다는 뜻이 아닙니다.

## 출력 해석

- `sensor_ok`: 연결·설정 상태. 센서값의 의학적 정확도 표시가 아님.
- `raw_ok`: 최근 1초 이내에 정상 길이의 FIFO 데이터를 받았는지.
- `contact`: `NONE`(조건 미충족), `SETTLING`(진입 확인 중), `CANDIDATE`(광량 기반 접촉 후보).
- `red_raw`, `ir_raw`: 센서 내부 18bit ADC 원시값. Teensy 아날로그 핀으로 읽는 값이 아님.
- `adc_rail`: 두 광학 채널 중 0 또는 최대 코드가 있는지. 이런 샘플은 추정 창에서 제외.
- `window_samples`: 계산 창에 모인 샘플 수. 200개가 차면 계산 후 175개를 남깁니다.
- `hr_ok`: 접촉 후보 유지 + 반복성 검사 + 연속 창 확인을 통과한 벤치용 주기 추정.
- `spo2_ok`: 위 조건 + 기존 라이브러리 유효성 + 라이브러리 검출 주기와 새 추정 주기 일치.
  무효일 때 대응 숫자 필드 생략. 임상적 신뢰도 표시가 아님.
- `hr_bpm`, `spo2_pct`: 유효할 때만 나오는 **벤치용 추정값**. 미측정값을 0으로 만들지 않음.

적색+IR 각각 100Hz 측정 후 4회 평균하여 25쌍/초를 받습니다. 접촉 안정화 뒤 첫 품질 검사는 약 8초,
이후 약 1초마다 갱신하며 출력은 10Hz 요약입니다. 모듈 위를 가렸을 때의 원시 신호 변화로
광학 취득을 먼저 확인하세요. HR/SpO2는 맥동 광학 입력이 필요합니다. 값이 나오더라도
손가락 접촉·움직임·주변광·교정이 검증된 것은 아니고 건강 판정에 사용하면 안 됩니다.
일반 물체나 마네킹 표면만으로 정상적인 HR/SpO2가 측정된다고 가정하지 않습니다.

샘플 누락, FIFO 정체/오버플로, 전원 리셋, I2C 실패 시 창과 유효 플래그를 폐기하고
2초 간격으로 다시 연결합니다. 연결 실패 시 원시값/추정값을 만들어 출력하지 않습니다.
Teensyduino 1.62의 Wire 내부 타임아웃을 사용하며 무한 센서 대기 루프는 없습니다.

사용자 조정은 스케치 위쪽 `LED_AMPLITUDE`와 `PRINT_PERIOD_MS`입니다.
LED 값은 0~255 전류 설정 코드이지 %/모터 전류가 아닙니다. 현재 60은 라이브러리 예제값입니다.
샘플레이트·평균 횟수는 알고리즘의 25Hz 가정과 연결되므로 임의 변경하지 마세요.

- `tests/test_optical_window.cpp`: 실제 스케치가 사용하는 `OpticalWindow`에 대해
  **컴파일 타임 assertion 21개 통과** (`-std=c++14 -Wall -Wextra -Werror -fsyntax-only`).
  미접촉 잡음, 두 채널 조건, 진입 유지, 이탈, 한 채널 상실, ADC rail, 재접촉 시
  새 100개 샘플, 리셋, 샘플 지연, millis 오버플로, 무효 계산, 75/25 창 이동을 확인했습니다.

  이 로그는 10Hz 요약이며 원본 25Hz 파형이 아닙니다. SpO2 알고리즘·실제 지연·정확도 검증은 아닙니다.

스크립트는 기본적으로 Teensy 도구의 `arm-none-eabi-g++.exe` 15.2.1을 사용합니다.
위치가 다르면 `-Compiler`로 지정합니다. 컴파일러의 상수식 평가로 검사하며,
MCU 명령을 실행하거나 시리얼 포트를 열거나 업로드하지 않습니다.

## 2026-10-03: 파형 반복성 시험 (`implemented`, 실물 재시험 전)

접촉 보정은 **미접촉/접촉 광량 분리**일 뿐, 심박수/SpO2 정확도 교정이 아닙니다.
기준 산소포화도계가 없는 현재 시험에서는 정확도 확인을 완료로 표시하지 않습니다.
`quality_verified=0`, `accuracy_verified=0`은 그대로 유지합니다.

사용자 RAW 로그에서 기존 피크 계산이 불규칙한 간격을 평균하여 출력하는 것이
확인되어, 시험 코드에 아래 신호 처리를 추가했습니다. 메인 Teensy 펌웨어·프로토콜·
다른 모터/센서 시험 코드에는 적용하지 않았습니다.

- 원시 배열은 보존하고 별도 배열에서 선형 추세 제거, 51점 이동 평균 기준선 제거,
  3점 평활화를 합니다. `RAW`에는 필터 전 값이 그대로 나옵니다.
- 8초 창에서 반복 주기를 찾고 두 채널 및 앞/뒤 절반의 주기가 일치하는지 검사합니다.
  두 번 연속 통과해야 수치를 출력합니다. **숫자를 특정 BPM 범위로 자르거나 이전 값으로
  대체하지 않습니다.** 반복을 충분히 관찰하지 못하는 긴 주기도 수치를 생략합니다.
- SpO2는 마지막 4초 원시 창에 기존 라이브러리를 사용합니다. 해당 라이브러리의
  검출 주기가 새 주기 추정과 다르면 `spo2_reason=LEGACY_PERIOD_MISMATCH`로 생략합니다.
  AC×DC의 32-bit 오버플로 방지는 두 채널 복사본에 공통 2의 거듭제곱 배율로 합니다.
  SpO2 보정 계수 변경·강제 100% 표시·의학적 임계값 추가는 없습니다.
- 무효 창, 손가락 제거, ADC rail, 샘플 정체, STOP/재연결/LED/접촉 기준 변경은
  이전 값과 연속 확인을 폐기합니다. 출력은 계속 비차단이며 로그 누락 횟수를 집계합니다.

### 초기 공학 설정 (`assumed`, 벤치 재시험으로 평가할 것)

`ppg_signal.h`의 값은 제조사 정확도 보증이나 의학적 기준이 아닙니다.
합성 파형과 제공된 단일 RAW 기록에 대한 개발용 설정이며, 다른 손가락·모듈·
접촉 압력·주변광에서 민감도/오검출을 검증해야 합니다.

| 설정 | 초기값 | 의미 |
|---|---:|---|
| 창 / 갱신 | 200 / 25쌍 | 약 8초 관찰, 1초마다 검사 |
| 주기 상관 제곱 | 0.36 | 양의 반복 상관 0.6 이상, 의료 신뢰도 아님 |
| 채널 상관 제곱 | 0.64 | RED·IR 같은 방향 변화 검사, 반사/진동도 통과 가능 |
| 주기 일치 여유 | 1샘플 + 짧은 주기의 10% | 채널·절반·연속 창·라이브러리 비교용 |
| 연속 창 | 2 | 서로 겹치는 창이며 독립된 정확도 시험이 아님 |

### 새 출력

- `DATA.signal_ok=1`: 벤치 반복성 검사 통과. 피부/생체/정확도 인증이 아님.
- `signal_reason=WAITING_WINDOW`: 새 샘플 수집 중.
- `CONFIRMING`: 한 창은 통과했으나 연속 확인은 아직 안 됨.
- `WEAK_PERIOD`, `NO_REPEATABLE_PERIOD`, `CHANNEL_MISMATCH`, `UNSTABLE_PERIOD`:
  현재 창 거부. 대응 수치 필드가 없는 것은 의도된 동작입니다.
- `PULSE`: 매 계산의 이유·확인 횟수·주기·상관·`calc_us`를 추가로 표시합니다.
  `calc_us`는 실제 MCU 계산 시간 관찰용이며 컴파일만으로 성능을 확인한 것이 아닙니다.
- `spo2_reason=ALGORITHM_ONLY`: 조건을 통과한 라이브러리 추정값일 뿐, 정확도 검증 전.

### 지금 사용자 시험 순서 (`planned`)

1. 모든 모터 전원을 분리하고 새 스케치를 업로드합니다. 이 변경에서는 업로드하지 않았습니다.
2. READY에 `build=pulse_quality_v3`인지 확인합니다. SDA18/SCL19, LED 코드 60은 유지합니다.
3. `CAL OPEN`을 보내고 손을 떼어 완료까지 대기(약 10초).
4. 손가락을 안정적으로 올린 뒤 `CAL FINGER`, 완료 후 `CAL_APPLY`.
5. `CAL_SHOW`에서 `applied=1`을 확인합니다. 설정은 RAM 전용이며 재부팅/재업로드 후 재실시합니다.
6. `MODE RAW`: 접촉 60초 → 제거 5초 → 재접촉 60초를 기록합니다.
   수치는 접촉 후 약 10초 이상 기다립니다. 품질이 부족하면 더 오래 숫자가 없어도 정상입니다.
7. 기록 뒤 `MODE DATA`, `STATUS`를 보내고 `RAW`, `PULSE`, 오류/누락 횟수를 함께 보냅니다.
   측정 도중 START/RETRY/LED/CAL 명령을 반복하면 창/보정이 초기화됩니다.
