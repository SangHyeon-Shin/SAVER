# 선택형 통합 벤치 테스트

연구용 시제품의 고정·방호된 시험대/마네킹 시험 전용입니다. 사람에게 사용하지 않습니다.
Jetson용 운용 펌웨어가 아니라 **시리얼 모니터로 사람이 조작하는 별도 스케치**입니다.
기존 단독 테스트, `teensy/`, `jetson/`, `protocol/`은 수정하지 않았습니다.

## 열 파일

`selectable_system_bench_test.ino`를 Arduino IDE에서 열고 Teensy 4.1 / USB Type Serial을
선택합니다. 시리얼 모니터는 115200, 줄바꿈은 New Line 또는 Both NL & CR입니다.
폴더 안의 `.h`와 `src/`를 함께 유지합니다. 외부 라이브러리는 기존 맥박 테스트와 같은
**SparkFun MAX3010x Pulse and Proximity Sensor Library**의 `spo2_algorithm`이 필요합니다.
검사 환경의 설치 버전은 1.1.2입니다. 다른 센서는 로컬 레지스터 드라이버를 사용합니다.

## 세 모드

| 명령 | 이 모드에서 읽는 센서 | 구동 가능 출력 |
|---|---|---|
| `MODE VACUUM` | A8 압력 센서 | 음압 모터 1·2 |
| `MODE COMPRESSION` | A16 리니어, Wire1 NAU7802 로드셀, VESC 응답 | 압박 VESC 전류 PID |
| `MODE PPG` | Wire MAX30102 | 측정용 RED/IR LED만 |
| `MODE NONE` | 정기 센서 읽기 없음 | 모터 정지 요청, 시작한 PPG shutdown |

부팅/USB 재연결은 `NONE`입니다. 모드 선택만으로 모터가 시작되지 않습니다.
다른 모드로 바꾸면 **기존 모터를 먼저 정지·ARM 해제**하고 새 모드에서 새 시작 명령을 받습니다.
전환 시 압박 0 A 송신이 대기 중이거나 이전 PPG shutdown을 확인하지 못하면 `NONE`에 남습니다.
문제를 해결한 뒤 `MODE ...`부터 다시 보냅니다. 재연결 때 밀려 있던 명령은 버립니다.

`STOP` 또는 `DISARM`은 어느 모드에서도 두 음압 출력과 압박 전류 요청을 멈춥니다.
센서 읽기는 선택 모드에서 계속합니다. **맥박 측정/LED까지 종료하려면 `MODE NONE`**입니다.
`STATUS`, `HELP`는 공통 명령입니다. 자동 상태 출력은 1초마다입니다.
명령 철자는 대문자로 정확히 입력합니다. `RUN`은 압박, `RUN1/RUN2/RUNBOTH`는 음압 전용입니다.
다른 모드의 명령이나 잘못된 명령은 거부하고 모터를 정지합니다.

모드 비선택은 **소프트웨어의 취득·구동 비활성화**이지 센서 VDD의 물리 차단이 아닙니다.
다른 펌웨어에서 LED/드라이버가 켜져 있었다면 전원을 모두 껐다 다시 켠 뒤 시험합니다.
0 A 요청, EN LOW, PWM 0은 실제 정지/제동/수직축 하중 유지를 입증하지 않습니다.
USB와 독립된 물리 전원 차단·기계적 지지/방호·VESC 통신 timeout이 필요합니다.

## 배선: 기존 핀 유지

전원을 모두 끄고 배선합니다. Teensy 입력은 0~3.3 V 전용입니다.

| 장치 | Teensy |
|---|---|
| 음압 1 VSP / EN / ERR / RUN | 24 / 26 / 27 / 25 |
| 음압 2 VSP / EN / ERR / RUN | 33 / 37 / 36 / 32 |
| 압력 센서 분압 중간점 | A8 = 물리 22 |
| 압박 VESC TX → Teensy RX / VESC RX ← Teensy TX | 28 / 29 (Serial7, 115200) |
| 리니어 센서 OUT | A16 = 물리 40, 센서 전원 3.3 V |
| NAU7802 SDA / SCL | 17 / 16 (Wire1, 0x2A) |
| MAX30102 SDA / SCL | 18 / 19 (Wire, 0x57) |

센서·통신 신호 GND는 공통 기준으로 연결하되 모터 전류 귀환과 분리합니다.
VESC 전원 출력 핀과 음압 모터의 +5 V 출력선은 Teensy 전원에 묶지 않고 각각 절연합니다.
음압 FG, 압박 Hall/엔코더 직접 입력, 구동 바퀴 모터는 이 스케치에서 사용하지 않습니다.
주행 모터 등 이번 시험 범위 밖 부하는 전원·제어 연결을 분리합니다.

현재 압력 환산은 사용자가 실제 설치했다고 한 **OUT → 4.7 kΩ → A8 → 10 kΩ → GND**입니다.
센서 5 V 모델의 명목 0.5~4.5 V 전송식을 사용합니다. 6.8 kΩ으로 바꾸었다면
`src/pressure_conversion.h`의 저항값도 반드시 맞춰야 합니다. 이 4.7/10 분압은 정상 출력용이며,
OUT 5 V 고장까지 보호하지 않습니다. ADC 기준 3.3 V도 명목값입니다.
ERR/RUN은 외부에서 3.3 V 호환·바이어스를 확보해야 하며 코드가 과전압을 보호하지 않습니다.

## 1. 음압만 시험

```text
MODE VACUUM
STATUS
ARM
RUNBOTH 6 6
SET1 10
SET2 10
STOP
```

`RUN1 6`, `RUN2 6`으로 한쪽만 시작할 수도 있습니다. PWM 문법 범위는 1~100%이며
권장 구동값/전류 상한을 뜻하지 않습니다. **시간제한 없이 수동 STOP까지** 구동하므로 상시 감독합니다.
예전 `RUN1 6 500` 같은 시간 인자는 거부합니다. 전원장치 전류와 모터 전류는 서로 다릅니다.

ERR LOW는 래치되며 구동 중인 채널의 오류는 두 음압 출력을 멈추고 ARM을 해제합니다.
원인을 고치고 ERR HIGH가 250 ms 이상 유지된 뒤 `CLEAR_ERR` 또는 채널별
`CLEAR_ERR1`, `CLEAR_ERR2`를 보냅니다. 이후 **ARM과 새 RUN**이 필요하며 자동 재시작하지 않습니다.
압력 ADC rail/범위 오류도 구동을 중단합니다. `run1/run2`는 신호 레벨이지 회전 입증이 아닙니다.

`ZERO`는 정지 후 현재 압력을 **상대 표시 기준**으로만 저장합니다. `relative_Pa`가 추가되며 원래
`pressure_Pa`와 전기적 이상 판정은 바뀌지 않습니다. `UNZERO`로 취소합니다. 공급전압 저하를
영점 보정으로 숨기지 않습니다. 압력 `pressure_ok=1`도 정확도·정상 VDD의 증명은 아닙니다.

사용자는 기존 공급전압/ERR 배선 문제의 해결을 보고했으나 실측 전압은 새로 제공하지 않았습니다.
**출력을 높일 때 스스로 꺼지는 현상은 아직 미해결**입니다. 이 코드는 원인을 고치거나
보호를 우회하지 않습니다. 낮은 출력의 개별 시험부터 시작하고 고출력 통합 시험은 보류합니다.

## 2. 압박 + 리니어 + 로드셀

### 지금 곧바로 RUN이 되는가?

**기본 배포 설정에서는 아닙니다.** 원래 `compression_linear_pid_test`의 미확인 보호 설정을
그대로 복제했고 임의로 승인하지 않았습니다. `MODE COMPRESSION`의 센서 읽기·보정·VESC 조회는
가능하지만 ARM/RUN은 `CHECK`의 모든 설정 검사와 실시간 조건을 통과해야 합니다.
음압/PPG는 이 압박 설정 잠금에 영향받지 않습니다.

설정 파일은 **이 폴더의 `src/bench_config.h`**입니다. 이전 단독 테스트의 파일을 수정할 필요 없습니다.
실제 측정/검토 뒤 이 통합판 파일에만 반영합니다. `CHECK,...,passed=0`의 이유가 그대로 구동 거부 이유입니다.
`BENCH_DRIVE_CONFIRMED`, VESC timeout·전류 설정 검증, 센서 고장 시험, 실제 양방향 여유거리,
시작/추종 오차·속도·가속도 한계 등이 아직 미설정입니다. 플래그만 일괄 true로 바꾸지 않습니다.
50 mm는 사용자가 지정한 경계이며 **끝점 목표나 정지 여유가 아닙니다**. 목표는 보정 범위와
소프트 경계 안쪽이어야 합니다. 리니어 ADC rail 검사는 중간 전압으로 뜨는 단선을 전부 검출하지 못합니다.

사용자 보고대로 물리 전원 차단은 있고, 리미트와 6번 보조접점은 없는 벤치 구성을 유지합니다.
미연결 핀의 HIGH를 정상 접점으로 취급하지 않습니다. 주행/임상 운용 허가를 뜻하지 않습니다.
보조접점이 없으므로 짧은 전원 차단처럼 센서/통신에 드러나지 않은 정지를 코드가 알아낼 수 없습니다.
비상정지/전원 차단 뒤에는 먼저 STOP하고 구동 상태를 해제한 다음에만 전원을 복구합니다.

### 보정·시작 순서

모터 주전원을 분리하고 이동부를 지지한 상태에서 진행합니다. 이 스케치에는 자동 홈이 없습니다.

```text
MODE COMPRESSION
STATUS
ZERO
```

수동으로 압박 방향(양의 mm)으로 **외부 자로 측정한 거리**만큼 이동한 뒤 `CAL measured_mm`입니다.
예를 들어 실제로 20 mm를 측정했다면 `CAL 20`입니다. 20을 그대로 복사해 쓰는 명목 보정이 아닙니다.
이후 수동으로 작업 원점으로 돌아옵니다. CAL은 5~60 mm의 측정 거리를 받으며, 목표 깊이는 그보다 작아야 합니다.

로드셀을 무부하로 둔 뒤:

```text
TARE
```

`OK,FORCE_CAPTURE_DONE,zero_known=1,calibrated=0`을 기다립니다. 실제 질량을 아는 기준 하중을
가한 뒤 `FORCE_CAL known_kg`를 보냅니다. 예: **실제 1 kg** 기준 하중이면 `FORCE_CAL 1`입니다.
다시 완료 메시지를 기다린 뒤 하중을 제거합니다. 각 캡처는 새 샘플 320개를 평균하고 3초를 넘으면 실패합니다.
무부하/기준 하중 raw 범위가 겹치면 보정을 거부합니다. N은 kg 보정값에 표준중력가속도를 적용한 값입니다.
영점·보정은 RAM에만 있으며 압박 모드를 새로 선택/재부팅하면 다시 합니다.

실제 보호 설정을 반영하고 작업 원점에서:

```text
TARGET 5 10
CHECK
ARM
RUN 3
STOP
```

이 예시는 이전 LM의 소규모 목표이며 동작 보증/의료 권장값이 아닙니다.
`TARGET depth_mm cpm`에서 깊이는 편도, cpm은 완전한 왕복/분, `RUN 3`은 3왕복입니다.
ARM 유효시간은 10초이며 매 RUN 시간은 최대 10분입니다. 기본 목표는 자동 구동되지 않습니다.
`ILIMIT A`, `INLIMIT A`, `GAINS kp ki kd`는 정지 중에만 바뀌고 ARM을 해제합니다.
명령 가능한 상한은 모터/전원에 안전한 값이라는 뜻이 아닙니다. VESC 자체 설정은 변경하지 않습니다.
오류 후 원인을 해결하고 `CLEAR` → `CHECK` → `ARM` → 새 `RUN`입니다.

**힘은 관찰용**입니다. 로드셀 보정/새 데이터는 구동 조건에 포함하지만 힘 PID나 힘 상한 정지는
구현하지 않았습니다. 명세가 없는 힘 임계값을 만들지 않았으며 가압 안전을 보증하지 않습니다.
로드셀 고정·보정 방향·기구 방호를 독립적으로 확인해야 합니다.

### 두 압박 참고 코드의 반영

| 항목 | 이번 통합판 |
|---|---|
| `test/lm/sketch_sep16a` | 수동 ZERO/CAL, 코사인 왕복, 위치→전류 PID, 미분 필터·anti-windup, 200 Hz 계산/50 Hz 전류 요청의 원형 |
| 원래 `compression_linear_pid_test` | 검증된 순수 C++ PID/환산/패킷 코덱을 복제, 설정 검사·RAW 점프/추종/일정 지연 감시, 정지 우선·유효 데이터 요구 |
| 회전 부호 | LM 기본 +1 대신 기존 단독 코드의 사용자 관측 기반 -1 유지(축 끝에서 +전류=CW, 압박=CCW). 설치 기구에서 별도 재확인 필요 |
| 전류 초과 | LM의 100 ms 지속 판정 대신 원래 단독 코드처럼 유효 VESC 샘플에서 초과 시 즉시 정지 |
| 원점 복귀 | LM의 추가 복귀 PID 경로는 구현하되 원래 설정처럼 `RETURN_TO_ZERO_ENABLED=false`. 끝 위치 오차가 있으면 자동 추가 구동 없이 오류 정지 |
| 지연 | LM처럼 긴 dt를 5 ms로 바꾸지 않고 20 ms 이상 제어 지연이면 오류 정지 |

종료/STOP은 VESC `SET_CURRENT(0)` 요청입니다. 능동 제동·정지 확인·수직축 유지가 아닙니다.
통신 오류·값 오래됨·부적합 펌웨어·센서 이상·UART 송신 막힘은 정지 래치로 처리합니다.
NAU7802 Wire1 거래도 코어 timeout 동안 지연될 수 있으므로 I²C 뒤 제어 deadline을 재검사합니다.
그 지연 동안의 독립 정지는 VESC timeout/물리 차단이 맡아야 합니다.

## 3. 산소포화도·심박수만

```text
MODE PPG
STATUS
MODE NONE
```

PPG 모드에서만 초기화하고 LED/취득을 시작합니다. 두 모터 계통은 정지 요청 상태입니다.
손가락 접촉·정착 후 여러 초의 데이터가 필요합니다. 기존 테스트의 접촉 히스테리시스,
200 샘플 창, 주기성·채널 일치·연속 확인, Maxim 정수 연산용 범위 축소를 유지했습니다.
접촉 소실·ADC rail·오래된 데이터·FIFO/통신 오류면 이전 추정치를 즉시 무효화합니다.
유효하지 않은 심박수/SpO₂는 **0으로 표시하지 않고 수치 필드를 생략**합니다.
MAX30102와 MAX30105는 part ID만으로 구분되지 않으므로 실물 모델도 확인해야 합니다.
출력은 미검증 벤치 추정치이며 진단/의료 판단에 사용하지 않습니다.

## 파일·검증 수준

- `implemented`: 모드 분리, 각 센서 취득/보정, 압박 PID 경로, 정지/오류/재연결 처리.
- `tested`: PC에서 실제 스케치를 mock I/O로 실행하고 Arduino CLI로 Teensy 빌드한 소프트웨어 시험.
- `assumed`: 기존 하드웨어 핀맵·센서/저항 구성 및 사용자의 LM 동작 보고. 이 통합판에서 재실측하지 않음.
- `planned`: 실제 결합 회로의 EMI/전원/왕복/힘/신호 품질 검증과 미설정 압박 보호값의 실측.

`src/`는 기존 순수 C++ 헤더 11개의 **이번 작업 시점 동결 복사본**입니다.
Arduino IDE가 외부 상대 경로 헤더를 스케치 빌드에 복사하지 않으므로 독립적으로 빌드할 수 있게 넣었습니다.
원본의 이후 변경은 자동 반영되지 않습니다. 세부 출처/검사 결과는 `VALIDATION.md`입니다.
