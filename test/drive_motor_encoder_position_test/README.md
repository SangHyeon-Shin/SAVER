# 주행 웜기어 모터 엔코더 위치 왕복 시험

`drive_motor_encoder_position_test.ino`는 Teensy 4.1, IBT-2/BTS7960 모듈 한 개,
24 V 5840-555 계열 웜기어 모터 한 개를 **무부하 벤치에서만** 시험하는 코드입니다.
의료 동작 코드나 Jetson USB 프로토콜 구현이 아닙니다.

정상 `RUN`은 시간이 아니라 A/B 쿼드러처 카운트로 `0 → +N → 0`을 수행합니다.
목표 부근 감속, 역전 전 PWM 0 및 정지 대기, 전체 타임아웃, 무펄스·역방향·불법
전이 검사를 포함합니다. 전원을 켜거나 USB를 다시 연결해도 자동으로 움직이지 않습니다.

## 1. 현재 확인된 배선표

아래는 저장소 `teensy/pinmap.h`의 **구동 모터 1** 배정입니다.

| 구간 | 출발 | 도착 | 주의 |
|---|---|---|---|
| 모터 전력 | 24 V PSU `+` | 정격 퓨즈 → BTS7960 `B+` | 현재 퓨즈가 없으므로 최종 장치 전에 추가. 브레드보드/얇은 점퍼 금지 |
| 모터 전력 | 24 V PSU `-` | BTS7960 `B-` | 굵고 짧은 전력선 사용 |
| 모터 권선 | BTS7960 `M+`, `M-` | 이 실물의 노랑, 하양 | 도통 및 BTS 단독 회전으로 확인한 현재 실물 기준; 두 선을 바꾸면 방향 반전 |
| 모듈 논리전원 | 안정된 5 V | BTS7960 `VCC` | `B+`와 다른 단자. 24 V 연결 금지 |
| 공통 기준 | 24 V PSU `-`, 5 V GND | BTS GND, Teensy GND, 식별 완료된 인코더 GND | 비절연 제어이므로 공통 GND 필수 |
| 정방향 PWM | Teensy `7` | 3.3→5 V 버퍼 → `RPWM` | 10 kHz, pin 8과 같은 PWM 그룹 |
| 역방향 PWM | Teensy `8` | 3.3→5 V 버퍼 → `LPWM` | 코드가 두 PWM을 동시에 활성화하지 않음 |
| 드라이버 허용 | Teensy `15` | 3.3→5 V 버퍼 → `R_EN`과 `L_EN` 둘 다 | 부팅 시 LOW. 버퍼 입력에 하드웨어 pull-down 권장 |
| 인코더 네 선 | 빨강, 검정, 파랑, 초록 | 역할 미확정 | 실제 VCC/GND/A/B를 확인하기 전 전원 및 Teensy 연결 금지 |
| 인코더 A | 실제 A로 확인한 선 | 검증된 0~3.3 V 경로 → Teensy `11` | 5 V 직결 금지 |
| 인코더 B | 실제 B로 확인한 선 | 검증된 0~3.3 V 경로 → Teensy `12` | 5 V 직결 금지 |
| 미사용 | BTS `R_IS`, `L_IS` | 연결 안 함 | 이 시험은 전류 측정 기능을 구현하지 않음 |

IBT-2 복제품에는 보통 5 V로 동작하는 `74HC244` 계열 입력 버퍼가 실려 있어,
Teensy의 3.3 V HIGH가 모든 보드에서 보장된다고 볼 수 없습니다. 권장 경로는
`74HCT244` 또는 `74AHCT244`를 5 V로 구동하고 Teensy 7/8/15를 그 입력에 넣는
방식입니다. 버퍼 가까이에 0.1 µF 바이패스 커패시터를 두고 입력은 10 kΩ 정도로
LOW 바이어스합니다. 실제 보드 부품명과 입력 HIGH 인식은 실측해야 합니다.

Teensy를 USB로만 공급하고 BTS 논리 5 V를 별도 벅에서 공급해도 되지만 GND는
공통이어야 합니다. 벅 5 V를 Teensy VIN에도 넣은 채 USB를 연결하려면 Teensy의
VIN–VUSB 연결 패턴을 분리해 역급전을 막아야 합니다.

## 2. 인코더 배선 식별과 레벨 변환 결정

판매 자료의 색상표와 현재 실물이 일치하지 않았습니다. 기존 노랑/하양 3.3 V 시험은
실제로 모터 권선을 읽은 것이므로 엔코더 검증으로 인정하지 않습니다. 아래 확인 뒤에만
`ENCODER_ELECTRICAL_INTERFACE_VERIFIED`를 `true`로 바꿉니다.

1. 24 V와 USB를 끄고 빨강/검정/파랑/초록을 모든 장치에서 분리합니다.
2. 실물 배선 추적 또는 제조사 실물 자료로 네 선의 VCC/GND/A/B를 식별합니다.
   저항값이나 색상만으로 전원 극성을 추측하지 않습니다.
3. 확인된 VCC/GND에만 전류 제한된 5 V를 공급하고, A/B는 Teensy에서 분리합니다.
4. A–GND와 B–GND를 오실로스코프 또는 로직 애널라이저로 측정하며 모터를 짧게
   회전합니다. 두 채널이 위상차를 두고 LOW/HIGH로 바뀌는지 확인합니다.
5. A/B 최고전압이 3.3 V 이하이면 각 신호에 1 kΩ 직렬 보호저항을 거쳐 11/12로
   연결할 수 있습니다. 이 저항은 과전압 변환기가 아닙니다.
6. A/B가 5 V라면 출력 형식을 확인합니다.
   - open-collector임이 확인되면 각 A/B를 3.3 V로 외부 pull-up할 수 있습니다.
   - 5 V push-pull이면 양방향 모듈이 아니라 5 V→3.3 V 입력용 버퍼/레벨시프터가
     필요합니다. 부품과 출력 주파수를 확인한 뒤 회로를 확정합니다.

확인이 끝나기 전 스케치의 `ENCODER_ELECTRICAL_INTERFACE_VERIFIED`는 `false`로
유지합니다. Teensy 4.1 입력은 5 V tolerant가 아닙니다.

## 3. 코드 잠금 해제와 명령

스케치 상단의 다음 값을 실측 후 설정합니다.

```cpp
ENCODER_ELECTRICAL_INTERFACE_VERIFIED = true;
BTS_CONTROL_INTERFACE_VERIFIED = true;
ENCODER_SIGN = 1;       // CAL_FWD signed_delta가 음수면 -1
MAX_TARGET_COUNTS = 0; // 보정 뒤 허용할 실제 편도 상한으로 변경
```

115200 시리얼 모니터에서 줄바꿈을 `New Line` 또는 `Both NL & CR`로 둡니다.

| 명령 | 의미 |
|---|---|
| `STATUS` | 상태, 위치 카운트, PWM, 엔코더 오류 표시 |
| `ZERO` | 정지·DISARMED 상태에서 현재점을 카운트 0으로 지정 |
| `ARM` | 10초간 유효한 1회성 구동 허용. 매 동작 전에 다시 필요 |
| `CAL_FWD 10 1000` | 10%로 논리 정방향 1초. 방향/카운트 보정 전용; 허용 범위 10~50% |
| `CAL_REV 10 1000` | 10%로 논리 역방향 1초. 방향/카운트 보정 전용; 허용 범위 10~50% |
| `RUN 500` | 0→+500 count, 정지 확인, 0으로 복귀 |
| `STOP` | PWM 0, EN LOW로 즉시 명령 정지 |
| `DISARM` | 출력 OFF 및 재ARM 요구 |
| `CLEAR_FAULT` | 원인을 물리적으로 제거한 뒤 래치 오류 해제 |

부팅 직후에는 세 잠금 중 하나 이상이 남아 있으므로 `RUN`이 거부되는 것이 정상입니다.

## 4. 실제 카운트와 거리 보정 절차

1. 모터/감속기를 단단히 고정하고 출력축에 눈에 보이는 기준선을 표시합니다.
2. 인코더 전기 시험을 끝낸 뒤 코드의 두 interface 값을 `true`로 바꿔 업로드합니다.
3. 24 V 전원 전류 제한을 1 A로 시작하고, `ZERO`, `ARM`, `CAL_FWD 10 1000` 순서로
   시험합니다. 출발하지 않으면 배선·축 구속·드라이버 상태를 먼저 확인합니다.
   사용자 계획대로 1.5 A, 최대 약 2 A의 짧은 무부하 시험은 정확한 모터 정격 확인
   전의 임시 벤치 범위일 뿐 최종 보호값이 아닙니다.
4. `EVENT,CAL_DONE`의 `signed_delta`가 양수인지 확인합니다. 음수면 전원을 모두 끄고
   A/B를 바꾸거나 `ENCODER_SIGN=-1`로 바꿉니다. 두 방법을 동시에 하지 않습니다.
5. 출력축 기준선을 정확히 한 바퀴 또는 가능하면 5~10바퀴 이동시키고 총 카운트의
   절댓값을 기록합니다. 웜기어 때문에 손으로 역구동할 수 없다면 여러 번의 짧은
   `CAL_FWD`와 즉시 `STOP`을 사용하고 회전 수를 영상/표식으로 셉니다.
6. `counts_per_output_rev = total_counts / measured_revolutions`로 계산합니다. 판매표의
   `11 pulses`가 모터축/출력축 기준인지, 한 채널 상승엣지인지, A/B x4 카운트인지
   이 실측으로 판별합니다.
7. 바퀴 직결이면 `mm_per_count = π × 실제 바퀴지름_mm / counts_per_output_rev`입니다.
   리드스크루면 `mm_per_count = 실제 리드_mm_per_rev / counts_per_output_rev`이고,
   중간 기어/풀리비가 있으면 실제 출력 회전비를 함께 반영합니다.
8. 원하는 이동거리 `D`는 `target_counts = round(D_mm / mm_per_count)`로 바꿉니다.
   보정한 기구의 물리 허용거리 이하 값을 `MAX_TARGET_COUNTS`에 넣습니다.
9. 처음 `RUN`은 매우 작은 N으로 수행하고 감속 시작점, 정지 초과량, 최종 원점 오차를
   각각 기록합니다. `SLOW_ZONE_COUNTS`를 초과 이동보다 충분히 크게 잡고,
   `SLOW_PWM_PERCENT`가 실제로 움직일 수 있는 최소 듀티보다 낮지 않게 조정합니다.
10. 전원 재인가 뒤 카운트 0은 실제 원점이 아닙니다. 통합 장치에는 홈/리미트 스위치를
    설치해 원점을 다시 찾아야 하며, 설치 전에는 저장된 카운트를 절대 위치로 믿지 않습니다.

## 5. 즉시 중단 조건과 한계

- 전원 전압이 반복해서 무너짐, 전류 제한 반복 진입, 축 정지, 비정상 소음, 급격한
  발열, 드라이버 보호 반복 동작이 있으면 물리 전원을 즉시 끕니다.
- 코드의 `STOP`, USB 연결 감지, 타임아웃은 배선 단락·MCU 정지·MOSFET 고장을 끊지
  못하므로 물리 차단기와 퓨즈를 대신하지 않습니다.
- 현재 코드는 BTS 전류센스, 홈/리미트, 실제 E-stop 보조접점, 부하 위치, 절대 원점을
  읽지 않습니다. 구동 기구나 사람/마네킹에 연결하지 않습니다.
- PWM 10~50%는 전류 10~50%를 뜻하지 않습니다. 전류는 부하, 역기전력, 전원 제한,
  드라이버와 모터 저항에 의해 결정됩니다.
