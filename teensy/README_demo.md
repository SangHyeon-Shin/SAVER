# 수동 배치 시연 펌웨어 — 2026-10-23

마네킹·벤치 연구용. 임상 사용, 사람 대상 시험용이 아니다.
`saver_teensy.ino`가 진입점이며 구현은 `src/demo/`에 있다.
Arduino IDE에서는 **이 폴더의 `teensy.ino`를 연다. 폴더 전체를 유지한다.**
보드 Teensy 4.1, USB Type Serial, SparkFun MAX3010x 라이브러리가 필요하다.
`test_saver_proto.cpp`는 Arduino 빌드에서는 제외되고 PC 시험에서만 실행된다.

## 현재 가능한 것과 아직 안 되는 것

- `implemented`: VESC 전류 지령 기반 리니어 위치 PID, NAU7802 보정·힘 취득·힘 상한 정지,
  블로워 2개/압력 취득·간헐 제어, MAX30102 추정치 취득, JSON/직접 명령 공통 인터록,
  음압 확보 뒤 유한 압박을 시작하는 로컬 `BOTH` 통합 시험.
- `tested`: PC 모의 USB/UART/ADC/I²C 시험과 Teensy 컴파일. 실물 통합 시험 아님.
- `planned`/미검증: 실제 정지거리·보호 임계·블로워 운전 시간·전체 연결 동작.
  원점 리미트가 없으므로 **자동 HOME/탐색/압박점 접촉 탐색은 지원하지 않는다.**
- HOME은 `HOME_UNAVAILABLE_NO_VERIFIED_LIMIT`로 거부한다. 모터를 움직이지 않고
  HOMING_DONE/CP_ZERO_SET를 보내던 이전 자리표시자는 제거했다.
- **기존 Jetson UI의 S1→HOME→자동 탐색 전체 시나리오는 이 빌드로 통과하지 않는다.**
  수동 시연 UI/브리지 흐름은 해당 담당자와 별도 합의가 필요하다. `protocol/`, `jetson/`,
  `ui/`는 수정하지 않았다. 수동 시험 준비 뒤 START/PAUSE/RESUME/STOP JSON은 시험 가능하다.

## 먼저 확인 — 압박은 아직 기본 설정으로 구동되지 않는다

기구에서 **분리한 모터의 정지 경로**만 먼저 시험하려면
[STOPTEST.md](STOPTEST.md)를 따른다. 로컬 CP STOPTEST는 고정 +1 A / 1초 단발 자극이며,
왕복·압박이나 정상 구동 인터록 해제 기능이 아니다. 기본 OFF, 부팅/재연결 시 자동 구동 없음.

`src/demo/src/bench_config.h`의 미확인 보호 설정을 임의로 true/숫자로 채우지 않았다.
센서 읽기·보정·PPG는 가능하지만 `CP PREPARE`/`CP RUN`은 이 검증 전에는 거부한다.
`CP CHECK`에 실패 항목과 최종 구동 거부 이유가 나온다.

필요한 실측/확인:

1. VESC의 독립 명령 timeout 설정과 UART 분리 시 정지 확인.
2. 센서 배선/불량 입력 시험과 실물 조립 상태의 방향·보호 설정 검증.
3. 수동 영점 양쪽의 실제 소프트 경계와 정지 여유. 2026-10-23 사용자는 50 mm가 목표,
   기구 끝은 약 +77 mm라고 정정했다. 요청 소프트 경계 -7 / +60 mm를 반영했지만 실제
   센서 장착 범위와 정지 여유는 별도 검증이다. 목표는 경계·보정 거리보다 작아야 한다.
4. 시작 위치/속도 허용치, 추종 오차, 센서 변화율·노이즈, 프로파일 속도/가속도 한계.
5. 위 검증 뒤 마지막으로 `BENCH_DRIVE_CONFIRMED`. 단순히 구동하려고 일괄 true로 바꾸면 안 된다.

LM 소스의 기본값은 ILIMIT 6 A, INLIMIT 2.8 A였다. 이 값은 실측으로 결정한 새 권장값이 아니다.
메인의 깊이/분당 횟수는 0/미설정으로 시작하며 TARGET을 보내기 전에는 압박하지 않는다.
메인은 PROJECT_STATE의 초회 6 A/정상 감시 12 A와 맞춰, 전류 명령 상한을 초회 6 A로 유지했다.
입력 전류, 모터 전류는 서로 다른 값이다. PSU의 10 A 정격을 모터 전류 한계로 취급하지 않는다.
상단/하단 스위치와 E-stop 보조접점은 사용자 설명대로 미장착이다. 없는데 정상이라고 보고하지 않는다.
이 스위치 생략은 **사람 없는 수동 벤치 치구 범위**에만 해당한다.

### 50 mm / 120회·분 요청의 계산과 반영 범위

현재 fw는 manual-bench-20261023-motion-plan이다. 경계는 -7 / +60 mm로 변경했다.
로컬 벤치 요청 문법 상한은 120회/분이며 PROJECT_STATE의 기존 설계 목표 110회/분과
구분한다. 목표 깊이·속도는 여전히 0/미설정으로 시작하고 부팅만으로 구동하지 않는다.
사용자 보고의 STOPTEST 통과는 리니어 정지 경로 확인에 한정해 기록했다.

아래 읽기 전용 명령은 STOPTEST 중에도 목표, ARM, 출력을 바꾸지 않는다.

    CP PLAN 50 120

| 계산 항목 | 현재 코사인 왕복식의 요구량 |
|---|---:|
| 한 왕복 시간 | 500 ms |
| 최고속도 | 약 314.159 mm/s |
| 최고가속도 | 약 3947.842 mm/s² |
| 모터 최고속도, 감속 1.5:1 / 리드 10 mm | 약 2827.43 rpm |
| 4극쌍 가정의 최고 전기속도 | 약 11309.73 ERPM |
| 5 ms 동안의 명목 최대 이동량 상계 | 약 1.571 mm |

수식은 v_peak = π D f, a_peak = 2π² D f², f = cpm/60이다. 이 계산은 simulated
운동학 요구량이며 실제 모터·기구 허용치나 측정 검증 결과가 아니다. 궤적 요청 상한은
이 요구량으로 계산하지만 MAX_MEASURED_VELOCITY와 SAMPLE_NOISE는 고장 감시 임계값이므로
다르게 취급하고 아직 0/미설정을 유지한다. 임의 배수를 곱해 센서 한계로 넣지 않는다.

이전 시작 위치 ±10 mm / 시작 속도 10 mm/s / 추종오차 15 mm 요청은 검토 대기이며
적용하지 않았다. 특히 시작 위치 ±10 mm는 위쪽 경계 -7 mm보다 넓다.
이전 센서 속도 5000 mm/s / 잡음 5 mm는 5 ms에 30 mm 변화까지 허용하게 되므로
실측 근거 없이 설정하지 않았다.

기존 20 mm CAL은 50 mm 목표를 포함하지 않는다. STOPTEST OFF 후 원점과 목표보다
넓은 실제 측정 거리로 재보정해야 한다. CAL만 하려고 기계 끝에 닿게 움직이지 않는다.
새 업로드는 RAM의 로드셀 보정·목표·힘 상한도 초기화한다.
정상 RUN에는 남은 제어·전기 설정 검증이 필요하며, 이 변경만으로 구동 잠금을 열지 않았다.

이 변경의 PC 검증: main 모의 시험은 기본 설정 476개 / 합성 fixture 575개 통과,
프로토콜 26개, 핀맵 19개, 실제 Maxim 라이브러리 합성 재생 14개 통과.
Teensy 4.1 실제 대상 컴파일·링크와 확정값 감사도 통과했다. 업로드·실물 구동은 하지 않았다.
이 결과는 50 mm / 120회·분의 실측 추종 성능을 의미하지 않는다.

## 직접 명령: 시리얼 모니터, 115200, Newline 또는 CRLF

모든 출력은 LF로 끝나는 JSON이다. 직접 명령 결과는 BENCH_LOG의 msg 안에 표시된다.
보정값/동작은 장치가 자동 추정해서 채우지 않는다. `<...>`는 확정한 값을 넣을 자리이며 그대로 입력하지 않는다.

### 1. 센서부터

```text
STREAM OFF
HELP
STATUS
PPG ON
```

`STATUS`에서 힘/압력/PPG/현재 위치의 진단을 볼 수 있다. 주기 요약은 기본 20 Hz이다.
직접 시험에서 스크롤이 빠르면 STREAM OFF로 주기 출력을 끄고 STATUS로 확인한다.
센서/제어/인터록은 계속 작동한다. STREAM ON으로 일반 telemetry를 다시 켜며 REMOTE 전환 시 출력도 복구한다.
손가락 접촉·신호 품질이 확보되기 전 HR/SpO2는 생략하며 임의 숫자로 대체하지 않는다.
SpO2/심박 추정의 임상 정확도를 검증한 것은 아니다. 종료는 `PPG OFF`.

#### 심박수·산소포화도 연속 표시와 벤치 진단 모드

이번 로컬 수정의 INFO `fw`는 `manual-bench-20261023-motion-plan`이다. `proto`/`caps`는 바꾸지 않았다.
업로드 없이 이미 장착된 펌웨어의 동작이 바뀌지는 않는다.

`PPG ON`은 일반 모드 취득과 **1초 간격 PPG_LIVE 표시**를 켠다. STATUS를 반복 입력하지 않아도 된다.
표시되는 숫자는 최신 추정 결과이지 매초 독립적으로 검증한 새 측정값이 아니다.
`PPG SHOW OFF`는 PPG 전용 반복 줄만 끄며, `PPG SHOW ON`으로 다시 켠다.
`STREAM OFF`는 일반 telemetry와 PPG 반복 표시를 모두 끄지만 취득은 유지한다.
따라서 PPG만 보고 싶으면 **STREAM OFF 후 PPG ON 또는 PPG DIAG ON** 순서로 입력한다.

사용자 로그의 `acquiring=1,contact=NONE,window_samples=0,reason=WARMUP`은 센서 인식은 됐으나
일반 접촉 검사에서 계산 창을 모으지 못한 상태다. 원인을 관찰하기 위한 선택적 벤치 명령:

```text
STREAM OFF
PPG DIAG ON
```

- `implemented`, PC 모의/실제 라이브러리 합성 입력 `tested`. 실물·임상 검증 아님.
- 광량 접촉 문턱, 별도 채널/주기 일치, 연속 창 확인을 **진단 경로에서만 우회**한다.
  데이터시트/의학적 판정값을 새로 추정해서 넣지 않는다. 일반 모드의 기존 문턱은 그대로다.
- 실제 FIFO 신규 100샘플(설정 25 Hz에서 약 4초)을 모아 설치된 Maxim 알고리즘을 호출한다.
  이후 신규 25샘플마다 다시 계산한다. 수신이 끊기면 오래된 창과 후보값을 버린다.
- 센서 ID·I²C·FIFO 오류, 0/레일 입력, 데이터 신선도, 정수 곱셈 보호, 알고리즘 자체 실패 플래그와
  결과의 기본 표현 범위는 유지한다. 실패를 0이나 과거 정상값으로 메우지 않는다.
- 결과는 `BENCH_LOG.msg`의 `PPG_DIAG` 줄에서 `candidate_hr_bpm` / `candidate_spo2_pct`로 보인다.
  `diagnostic=1,clinical_validated=0`이며, 이 줄의 유효 플래그는 라이브러리가 계산값을 냈다는 의미일 뿐
  실제 생체 신호나 정확도를 검증한 것이 아니다. 두 값은 각각 성공한 경우에만 붙는다.
- 진단 후보는 **정상 tel의 ppg_hr_bpm/spo2_pct로 전송하지 않는다.** Jetson 판단이나 모터 인터록에
  사용하지 않는다. 원격 제어 전환/USB 연결 변경 시 진단 우회를 취소한다.
- `PPG DIAG OFF`는 일반 검사로 복귀해 새 창을 모은다. `PPG OFF`는 취득/진단/반복 표시를 중지한다.
  PPG 취득 시작·모드 변경은 압박 정지 상태에서만 한다. 출력 SHOW 토글은 취득을 바꾸지 않는다.
- `PPG_NOT_FOUND`는 이 검사들보다 앞선 센서 인식 실패라 이 모드로 해결하지 않는다.
  `ALGORITHM_NO_ESTIMATE`이면 접촉 추가 검사를 생략해도 라이브러리가 계산에 실패한 것이다.

### 2. 압박부 보정·준비

기존 안전한 보정 방법으로 기준 위치와 실제 이동 거리를 잡는다. 보정 명령 자체는 모터를 돌리지 않는다.

```text
CP ZERO
CP CAL <실제로_이동한_양의_거리_mm>
```

CAL 뒤 기준 위치로 복귀하고 멈춘 뒤 진행한다. ZERO는 새 RAM 보정을 시작하고 CAL을 무효화한다.
기존 리니어 EEPROM 보정은 부팅 때 읽으며, 위 명령으로 EEPROM 원본을 덮어쓰지 않는다.
센서/기구 설치가 바뀌면 보존된 값이 있어도 영점·방향·실측 거리를 다시 확인한다.

```text
CP TARE
CP FORCE_CAL <실제로_올린_기준_질량_kg>
```

TARE 완료 로그를 기다린 뒤 기준 질량을 가하고 FORCE_CAL을 보낸다. 완료를 기다리고 질량을 제거한다.
질량은 0 초과 100 kg 이하이며 센서·치구 허용 하중을 넘기지 않는다. 평균 320개의 신규 샘플을 사용한다.
두 측정 구간이 겹치거나 레일/시간 초과면 보정을 인정하지 않는다. 힘은 N으로 환산한다.
보정은 RAM에 있어 재부팅하면 다시 필요하다. USB 단순 재연결은 완료된 센서 보정을 지우지 않는다.
NAU7802 오류 후 재시험은 `CP SENSOR_RETRY` → TARE → FORCE_CAL. 자동 재시작은 없다.

```text
CP TARGET <시험_깊이_mm> <분당_완전_왕복_횟수>
CP FORCELIMIT <확정한_벤치_힘_상한_N>
CP ILIMIT <검토한_모터_명령_전류_상한_A>
CP INLIMIT <검토한_입력_전류_정지_기준_A>
CP CHECK
```

힘 상한은 처음에는 0/미설정이며, 설정 전에는 압박을 거부한다. 입력 허용 상한 600 N은 D-30의
벤치 시험 상한이지 임상 상한이나 모든 치구에 안전한 값이 아니다. 더 낮은 치구 한계를 우선한다.
CHECK가 실제 검증 설정/실시간 상태를 모두 통과했을 때만:

```text
CP PREPARE
CP RUN 3
STOP
```

RUN 3은 3회 완전 왕복이다. RUN만 보내면 1회. 모든 RUN은 사용자 요청의 최대 10분 제한을 받는다.
시작/종료의 위치 오차, 추종·힘·전류·센서·VESC·시간 이상은 정지한다. 기구 끝을 원점/목표로 쓰지 않는다.
PREPARE는 **수동 벤치 기준 확인**이지 자동 HOME/접촉 탐색 완료가 아니다. 설정 변경·STOP 후 다시 필요하다.
`STOP`은 압박 정지 요청이며 **흡착은 유지한다**. VESC 전류 0은 능동 제동/위치 유지 보증이 아니다.
고장은 원인을 제거하고 `CP CLEAR`; 자동으로 RUN을 다시 보내지 않는다.

### 3. 음압부

센서 분압은 사용자가 실제로 설치한 위 4.7 kΩ/아래 10 kΩ 기준이다. 공급전압 이상을 영점 보정으로 숨기지 않는다.
센서 OUT 5 V까지 입력될 경우 이 분압만으로 ADC 3.3 V 초과를 막지 못하므로 전기적 보호를 따로 확인한다.

```text
VAC CONFIG <듀티_pct> <최대_연속_ON_ms> <도달_안정_ms> <해제_압력대역_kPa_양수> <해제_안정_ms>
VAC ARM
VAC RUNBOTH <모터1_pct> <모터2_pct>
VAC OFF
```

운전/해제 시간·대역은 미확정이므로 기본 0이다. 팀이 확인한 값을 넣기 전에는 구동/자동 해제 판정을 막는다.
RUN1/RUN2도 가능하며 수동 듀티 시험도 최대 연속 ON 시간을 적용한다. 시간 만료/압력 무효/ERR는 정지한다.
`VAC CLEAR_ERR`는 원인이 없어지고 ERR가 안정적으로 정상인 뒤에만 해제한다. 고장/시간 제한을 우회하지 않는다.

`VAC ON`은 D-27 정책의 자동 간헐 제어다: 목표 −22.5 kPa에서 정지, −20 kPa보다 약해지면 재기동.
설정한 연속 ON 상한에 도달하면 −20 kPa 이하인 경우 도달 압력을 정지 기준으로 삼고, 미달이면 정지·고장 처리한다.
실제 흡착 도달 판정을 기다린 후에 압박을 준비한다. 체크밸브/블로워 온도·저유량 허용시간은 미검증이다.
`VAC OFF`는 출력 OFF일 뿐 즉시 흡착 해제 보증이 아니다. 압력 대역/시간을 만족해야 mot.vac_released가 true다.
압박 중 VAC 설정/해제를 거부하므로 먼저 STOP한다.

#### 압력센서를 분리한 블로워 단독 진단

`implemented`, PC 모의 `tested`; 실물 재부팅 원인·무센서 운전·블로워 허용 운전 시간은 미검증이다.
사람이나 마네킹을 고정하는 용도가 아니라, **흡착 하중을 지지하지 않는 벤치의 블로워 단독 진단**이다.
물리 비상정지를 유지하고, 배선 변경 전에는 USB와 모터 전원을 모두 끈다. 센서의 VDD/OUT/GND를
분리하되 드라이버와 Teensy의 신호 기준 GND는 제거하지 않는다. ERR/RUN 전압 확인은 별도로 필요하다.

압력 미측정 상태를 정상 압력으로 꾸미지 않도록 기본 OFF인 명시적 직접 명령을 추가했다.
다음 CONFIG 값은 사용자가 선택한 시험 설정(22%, 5분 상한, 2초, 1.5 kPa, 3초)이며,
블로워가 5분 동안 안전하게 운전한다는 실측 근거가 아니다. 무센서 상태에서는 안정/해제 설정을
판정에 사용하지 않고 **연속 ON 시간 상한만 적용**한다.

```text
STREAM OFF
VAC SENSORLESS ON
VAC CONFIG 22 300000 2000 1.5 3000
VAC CLEAR_ERR
CLEAR_FAULT
VAC ARM
VAC RUNBOTH 22 22
```

- 한 대만 비교할 때는 RUNBOTH 대신 `VAC RUN1 22` 또는 `VAC RUN2 22`를 사용한다.
- 이 모드에서 `STOP`, `DISARM`, `VAC OFF`는 블로워 출력을 끄고 재구동 허가를 취소한다.
  일반 모드의 STOP/DISARM은 기존대로 압박만 멈추고 흡착을 유지하므로 의미를 구분한다.
- **ERR LOW 정지/잠금, 정상 250 ms 뒤 수동 오류 해제, 듀티 범위와 연속 ON 시간 제한은 유지**한다.
  USB 연결 변경, 손상/미완성 명령도 이 모드의 블로워를 정지한다. 자동 재시작하지 않는다.
- A8을 읽지 않고 `vac_kPa`를 생략한다. STATUS는 `sensorless=1,pressure_feedback_enabled=0`이다.
  흡착 완료/해제 완료를 보고하지 않으며 `VAC ON`, 압박 준비/구동, BOTH 통합 시험을 거부한다.
- 원격 전환은 출력을 끄고 거부한다. 진단 중 Jetson 요청으로 모터가 켜지지 않는다.
- USB 재연결 시 무센서 표시 모드는 RAM에 남되 출력/ARM은 취소된다. 새 ARM/RUN이 필요하다.
  실제 재부팅 시 이 모드는 기본 OFF로 돌아가므로 다시 명시적으로 켜야 한다.
- 정상 복귀는 먼저 `VAC OFF`. 모든 전원을 끄고 센서를 복원한 뒤 `VAC SENSORLESS OFF`로 복귀하고,
  압력 전압/대기압 환산을 다시 확인한다. 센서가 없는데 일반 모드로 전환하지 않는다.

#### 재부팅 원인 기록

Teensy 코어에 남은 CrashReport와 리셋 상태 레지스터를 **부팅 출력 OFF 상태에서 RAM에 복사**한다.
USB가 연결되면 `BOOT_DIAG`, `BOOT_RESET_REGISTER`, 가능할 때 `CRASH_REPORT`를 JSON BENCH_LOG로
출력하며, 저장한 내용은 `BOOT INFO`로 다시 볼 수 있다. 직접 Serial 대기/출력이나 제어 루프 안의
CrashReport 렌더링은 하지 않는다. 텍스트 저장/출력은 길이 제한이 있고 잘림을 표시한다.
정상 tel/mot와 프로토콜 명령은 바꾸지 않았다.

`crash_record=1`이면 코어 오류 기록이 남았다는 뜻이다. `0`이어도 전원 강하나 기록 불가 오류까지
배제하지 않는다. 업로드·전원 차단이 이전 오류 기록을 지울 수 있으므로, 새 빌드에서 증상이
재발하면 전원을 다시 끄기 전에 출력되는 `BOOT_DIAG`/`CRASH_REPORT` 전체를 저장한다.

### 4. 음압 + 압박 통합 시험 (`BOTH`, 직접 벤치 명령만)

`implemented`, PC 모의 `tested`; 실물 통합 구동은 미검증이다. Jetson JSON 명령/상태머신은
추가하거나 바꾸지 않았다. `BOTH`는 별도 운용 상태가 아니라 기존 제어기를 순서대로 요청하는
벤치 보조 기능이다. PPG를 자동으로 켜지 않는다.

사용자가 설명한 공급 전류 배분은 **블로워 각각 3 A + VESC 입력 3 A**다. 총 9 A이며,
10 A 전원의 계산상 잔여는 1 A다. 이는 모터 정격이나 총전류 실측/제어를 뜻하지 않는다.
블로워 듀티 약 22에서 각각 약 3 A, VESC 모터 전류 지령 10 A에서 공급 전류 약 0.6 A를
봤다는 사용자 관찰이 있다. **기동·부하 변화 때 최대값, 동시 시험 결과는 아직 미검증**이다.
VESC 모터 측 전류와 입력 전류를 혼동하지 않으며, 이 관찰만으로 메인의 초회 모터 지령
상한 6 A를 10 A로 올리지 않았다. 입력 3 A는 수신값 기반 정지 기준이지 순간 하드웨어 제한이 아니다.

먼저 앞 절의 리니어/로드셀 보정·목표·힘 상한과 구동 보호 검증을 끝내고, 압박 정지/음압 OFF,
압력관 대기 개방 상태에서 시작한다. **대기 개방 −24.60 kPa 오류를 먼저 해결한다.**
설정한 해제 압력대역/시간을 만족해야 시작할 수 있다. 이것은 잘못된 영점으로 흡착 완료를
판정하지 않기 위한 검사이며, 센서 정확도 교정을 대신하지 않는다.

```text
VAC CONFIG 22 <최대_연속_ON_ms> <도달_안정_ms> <해제_압력대역_kPa> <해제_안정_ms>
CP INLIMIT 3
BOTH POWER <블로워1_최대_공급_A> <블로워2_최대_공급_A> <같은_전원의_기타_최대_부하_A>
CP PREPARE
BOTH CHECK
BOTH RUN 3
```

- 듀티 22는 사용자 관찰값일 뿐 **3 A 정전류 설정이 아니다**. 사용할 듀티에서 기동 포함
  전류를 재고 `BOTH POWER`에 상한을 기록한다. 각 블로워 상한은 3 A 이하, 기타 부하 포함
  합계 + 압박 입력 배정 3 A는 10 A **미만**이어야 한다. `other=0`은 같은 전원에 기타 부하가
  실제로 없을 때만 쓴다. 총전류 센서는 현재 사용하지 않으므로 이 입력값을 자동 검증할 수 없다.
  `BOTH POWER 3 3 0`은 이 조건을 실측 확인했을 때만 사용할 수 있는 예다.
- `CP INLIMIT`은 3 A 이하를 허용한다(기본 2.8 A도 이하). `CP ILIMIT`은 **모터 측 지령 한계**로
  별개이며 기존 설정/보호를 유지한다. 강제로 정확히 3 A를 소비하게 하는 기능은 없다.
- POWER는 준비 허가를 취소하므로 **그 뒤 CP PREPARE**한다. VAC 설정/듀티/ARM/ON 변경이나
  USB 재연결 뒤에는 POWER를 다시 기록한다. 기존 보정값을 새로 만들거나 지우지는 않는다.
- `BOTH CHECK`는 준비 안 된 첫 이유를, `BOTH STATUS`는 대기/구동/공급 예산을 보여 준다.
  CHECK가 통과해도 실물 안전 검증을 보증하지 않는다. 기본 구동 잠금은 그대로다.
- RUN은 먼저 블로워 2개를 자동 제어하고, 유효한 압력으로 안정된 흡착이 확인돼야 압박을 시작한다.
  압박 시작 직전에도 같은 인터록을 다시 검사한다. 리니어/로드셀/압력을 계속 읽는다.
  위 예는 **이미 설정한 깊이·분당 횟수로 3회 왕복**이다. RUN 인수는 듀티나 전류가 아니다.
- 흡착 대기는 CONFIG의 최대 연속 ON 시간과 같은 길이를 **총 대기 상한**으로도 적용한다.
  그 안에 안정 도달하지 못하면 블로워 출력을 끄고 압박을 시작하지 않는다. 압박 시작 후에는
  흡착 유지 제어를 병행한다. 요청부터 총 10분 상한 또는 요청 횟수 완료 시 압박을 멈춘다.
  압박 종료/일반 고장 시에는 흡착을 자동 해제하지 않는다.
- `STOP` / `BOTH STOP`은 압박을 멈추고 대기 중 자동 시작도 취소하며 **음압은 유지**한다.
  실제 기구 정지를 확인하고 필요할 때 `VAC OFF`로 별도 해제한다. USB 단절·손상 명령·센서 고장도
  미완료 요청을 취소한다. 재연결/오류 해제 뒤 자동 재시작하지 않는다.
- 음압 단독의 5 A × 2 계획은 전원 10 A 전부이므로 기동/기타 부하 여유가 없다. 듀티를 전류로
  바꾸거나 자동으로 상향하지 않았다. PSU CC 설정, 기동 전압 강하·총전류·VESC 회생은 실측한다.

## Jetson JSON 제어와 직접 제어의 구분

- 기본 v1.1: GET_INFO/GET_STATUS/PING/GET_FAULTS는 seq만 필요하다.
- 그 밖에는 INFO의 boot_id를 bid로, 증가하는 aid를 넣는다. wire 필드 v는 여전히 1이다.
- 동일 요청 재전송은 최초 ACK를 재전송하고 동작을 반복하지 않는다. 거부 ACK도 그대로 보존한다.
- STOP_CPR/PAUSE_CPR/DISARM/DRIVE_STOP은 완전한 JSON 구조·정확한 명령명을 확인한 뒤,
  bid/aid/버전 검사에 앞서 해당 정지 출력을 적용한다. VACUUM_OFF는 이 예외가 아니다.
- INFO에는 실제 구현한 AID/MOT만 광고한다. DRIVE/HEAD_HOLD/CP_ZERO는 광고하지 않는다.
  미합의 고장 코드를 지어내거나 기존 코드 의미를 바꾸지 않는다. 대응 코드가 없는 벤치 고장은
  FAULT 상태와 BENCH_LOG 사유로 보고하고, faults를 빈 배열로 꾸미지 않고 생략한다.
  GET_FAULTS는 합의된 코드의 err와 FAULTS_END를 반환하나 미할당 벤치 고장이 있어 FAULTS capability는 광고하지 않는다.
  원인 제거 후 `CLEAR_FAULT` 또는 원격 `RESET_FAULT`로 해제를 요청한다. 구동은 다시 준비해야 한다.
- 직접 시험이 제어권을 갖고 있으면 JSON 구동 요청을 거부한다. 조회·정지는 항상 처리한다.
- 원격 ARM은 PPG 관측도 시작한다. 직접 시험은 `PPG ON`으로 별도 시작한다. 센서 취득만으로 압박을 시작하지 않는다.

직접 보정/목표 설정/CP PREPARE를 마치고 압박이 정지한 상태에서:

```text
CONTROL REMOTE
```

그 후 Jetson 시험 클라이언트가 GET_INFO로 세션을 확인하고 START_CPR을 보낼 수 있다.
시리얼 모니터와 Jetson 브리지가 같은 포트를 동시에 열면 안 된다. 열고 닫으면 준비/제어권은 취소되므로,
Jetson 시험 클라이언트가 연결된 같은 세션에서 명시적인 벤치 준비를 해야 한다. 기존 UI에 이를 몰래 추가하지 않았다.
원점 리미트 없는 전체 UI 초기화 문제를 성공 이벤트로 숨기지 않는다.

```json
{"v":1,"t":"cmd","seq":1,"cmd":"GET_INFO"}
{"v":1,"t":"cmd","seq":2,"cmd":"GET_STATUS"}
{"v":1,"t":"cmd","seq":3,"cmd":"PING"}
{"v":1,"t":"cmd","seq":4,"cmd":"PAUSE_CPR"}
{"v":1,"t":"cmd","seq":5,"cmd":"STOP_CPR","reason":"USER_STOP"}
```

START_CPR/RESUME_CPR는 모든 인터록을 다시 검사한다. RESUME는 CPR_PAUSED에서만 받는다.
임의의 중간 위치에서 재개하지 않으며, 기존 리니어 제어의 시작 원점/안정 조건을 다시 만족해야 한다.
PAUSE ACK는 수락만 뜻한다. 전류 0 송신이 끝나고 신규 VESC 정지값과 리니어 속도가 안정된 뒤 CPR_PAUSED가 된다.
STOP/FAULT 상태나 ACK만으로 실제 완전 정지가 확인됐다는 음성을 내면 안 된다.
원격 제어에서는 유효 JSON이 2초 동안 없으면 압박을 즉시 정지하고 음압은 유지한다.
미확정 T_comm의 30초 지속은 하지 않는다. 신규 START/RESUME는 최대 10분의 유한 시험이다.

작업 트리의 구형 v1.0 Jetson을 사용할 때만 정지 중 명시적으로 `CONTROL REMOTE_V1`을 선택한다.
seq만 있는 구형 요청을 받고 최근 8건의 ACK를 저장한다. INFO도 proto 1.0/caps 빈 배열로 응답한다.
**aid가 없다는 이유로 자동 강등하지 않는다.** v1.1 연결은 `CONTROL REMOTE`를 사용한다.
구형 형식에는 bid/aid를 통한 과거 세션 배제가 없다. 연결이 끊기면 과거 동작 요청을 재송신하지 않는다.

## 전원/정지의 제약

USB 재연결은 RAM 초기화가 아니지만 압박 구동 허가/미완료 명령/준비 상태는 취소한다.
리니어 저장 레코드 4096..4135를 보존하고 별도 4160..4175에 이중 기록으로 boot_id를 쓴다.
재부팅/전원 차단은 RAM 하중 보정/설정/준비를 지운다. boot_id 기록에 실패하면 ARM/구동을 허용하지 않는다.
일반 DISARM/압박 FAULT/통신 단절은 흡착을 임의로 해제하지 않는다. 압력 센서/블로워 자체가 고장 나면
음압 출력을 정지하고 압박도 멈춘다. 물리 E-stop의 전력 차단 범위를 소프트웨어로 보증하지 않는다.

**Teensy를 Jetson USB로만 급전하면 USB 전원 차단 때 프로그램도 멈춘다.** 그 뒤 STOP을 보낼 수 없다.
독립 VESC timeout, 블로워 EN/VSP 외부 풀다운, 물리 전원 차단이 필요하다.
Teensy의 USB/3.3 V에서 모터를 급전하지 않는다. 모터 측 +5 V 출력도 연결하지 않는다.
센서 소비 전류/Jetson 전원 여유, 역급전, 실제 정지는 별도 실측한다.

## 검증 명령

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File teensy/tests/demo/check_main.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File teensy/tests/demo/check_ppg_diag_replay.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File teensy/tests/check_pinmap.ps1
arduino-cli compile --fqbn teensy:avr:teensy41 --warnings all --build-path <임시_빌드_경로> teensy
```

PC 표준 시험: `g++ -std=c++11 -Wall -o <임시_실행파일> teensy/test_saver_proto.cpp` 뒤 실행한다.
새 합성 fixture는 PC 시험 전용이며 Arduino가 읽지 않는다. 실기 업로드/통전 시험은 자동 실행하지 않는다.
