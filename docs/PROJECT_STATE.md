## 5. 주장 수준 표기 규칙

보고서·발표·커밋 메시지에서 아래 5단계를 반드시 구별한다. `docs/evidence.csv`의 `level` 열과 같다.

| 수준 | 의미 |
|---|---|
| `implemented` | 코드/하드웨어에 구현되어 동작 확인됨 |
| `tested` | 시험으로 정량 검증됨. 시험 ID 필수 |
| `simulated` | 해석·시뮬레이션 예측. 실측 아님 |
| `assumed` | 문헌·가정. 본 과제에서 검증하지 않음 |
| `planned` | 미구현. 보고서에서 완료로 서술 금지 |

## 6. 열려 있는 리스크

- 최종보고서: 9/16 제출, 10/2 오류 수정본 송부(정오표 56항목). T1~T4 실측은 10/12~14
- **유효 흡착 면적 부족**(§3 `A_eff`): 결선 질의응답의 첫 질문 후보. 결과를 그대로 제시하고 재설계 방향으로 설명한다
- **음압 해제 판정값 미설정**이면 v1.1 펌웨어 `ARM` 불가 → 10/6 벤치값 확정이 10/7 이후 일정의 선행 조건

- `docs/specs/` 파일 확장자 불일치 → `tools/fix_extensions.py`
- 과거 보고서에서 EAPD 계수 오류가 4개소로 전파된 이력 → 제출 전 `tools/consistency_audit.py` 필수 실행. **`.docx` 는 검사하지 않으므로 텍스트로 추출해 검사할 것**
